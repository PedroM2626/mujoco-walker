# Runtime dependencies for Phases 1-3 (root directory: WalkerRagdoll-v0).
# Install: pip install -r requirements.txt   (needs Python 3.10+)
#
# Verified in .venv: Python 3.11.9, gymnasium 0.29.1, mujoco 3.2.3, torch 2.4.1+cu121,
# numpy 1.26.4, mlflow 3.16.1 - the combination this file resolves to, and the suite that
# passes in it (41 tests, 7 of them phase-4 only).
#
# It is NOT installable on the Python 3.8 venv that shipped with this repository, and used to
# claim a version it could not reach: `mlflow>=3.0` publishes no Python 3.8 distribution
# (`pip download "mlflow>=3.0"` -> "No matching distribution found") and neither does
# `numpy>=1.26.4` (1.25 dropped 3.8). Two of the three reasons the ragdoll trainers could not
# log to MLflow live in that line. The 3.8 venv is kept as `.venv-py38-backup/`; swapping it
# back is two `mv` commands, and the rollout it produces is bit-identical to the new one
# (200 steps from seed 7: reward -2506.5429333387096 in both).
#
# Do NOT use this file for Phase 4 (openai_walker/): those scripts make Walker2d-v5,
# which does not exist before gymnasium 1.0. Use requirements-phase4.txt there.
# Splitting the two is deliberate - the ragdoll tests and trained checkpoints are pinned
# to the 0.29 wrapper API, and bumping this file would move that ground under them.
gymnasium[mujoco]>=0.29.1,<1.0
torch>=2.1.0
# Deliberately no `numpy<2`: this torch build works under numpy 2 (measured here -
# `pip install numpy==2.1.3` then `import torch` succeeds, with one __array_wrap__
# DeprecationWarning), and no script in the repo uses a name numpy 2 removed (np.float_,
# np.NaN, np.in1d, np.row_stack, np.product: grepped, zero hits). 1.26.4 is simply what the
# venv this file was verified against resolved to.
numpy>=1.26.4
# Pinned, not floored: benchmarks/walker_ragdoll_golden.json holds reference trajectories
# recorded under mujoco 3.2.3, and tests/test_env_golden.py compares rewards at 1e-9. A newer
# solver library can move those bits; re-record the golden file deliberately if you bump this.
mujoco==3.2.3
# gymnasium[mujoco]'s video recording and env.capture_image() import imageio lazily, so the
# dependency only shows up when a trainer asks for RecordVideo or a snapshot - and then as a
# ModuleNotFoundError from inside the rollout loop.
imageio>=2.31.0
imageio-ffmpeg>=0.4.9
# mlflow>=3, not 2.x: mlruns.db in this repo carries schema revision b7e2c1a4d9f3, written
# by mlflow 3.x. mlflow 2.17.2 refuses to open it (alembic "Can't locate revision
# identified by 'b7e2c1a4d9f3'"), so with the old pin `mlflow ui` and every log call fail
# against the repo's own history. The .venv shipped 2.17.2, which is why logging appeared
# to work in code but produced nothing.
mlflow>=3.0
pandas>=2.2.0
scipy>=1.11.4
tqdm>=4.66.1
tensorboard>=2.15.1
scikit-learn>=1.3.2
